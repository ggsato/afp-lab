# AFP Lab v0.7 — Radio Coverage Map

v0.6のMap Plannerに、単一基地局からの予測RSSI・受信マージンの面的表示を追加。AFP通信スタック、仮想E220、Recorder、Collector、Observatoryは変更していません。Python 3.10以上、標準ライブラリのみ。既存のField JSONとDEMキャッシュを再利用できます。

## Windowsで起動

別フォルダにZIPを展開してコマンドプロンプトで実行します。

```cmd
cd /d "%USERPROFILE%\Downloads\afp-lab-v0.7\afp-lab"
python -m unittest -v
python planner.py --cache "%USERPROFILE%\Downloads\afp-lab-v0.4\afp-lab\dem-cache" --open
```

v0.6のサーバーが動作中なら、先にそのコマンド画面でCtrl+Cを押して停止してください。ブラウザが開かない場合は http://127.0.0.1:8765/ を開きます。キャッシュの実際の保存先に合わせて変更してください。`--config` で既存Field JSONを指定して起動することもできます。

## 到達マップの使い方

1. Field Configの「Field JSONを開く」で、以前保存した自宅などの配置を読み込みます。新規フィールドでは基地局1台だけでも計算できます。基地局のアンテナ地上高は端末設定で編集し「入力を反映」を押します。
2. 地図の下の **Coverage Map** で基準端末、半径、格子間隔、仮想受信アンテナ地上高を選びます。まず半径3km、200m間隔を推奨。初期値は5km / 200m / 1.5mです。
3. 必要に応じ右側「実験設定 → 伝搬モデル・無線の設定」で送信出力、受信閾値、追加損失、周波数、アンテナ利得合計、断面間隔を設定します。モデルは従来の点対点実験と共通です。
4. 「到達マップを計算」を押します。Python画面にDEM取得・格子計算の進捗が表示されます。初回は必要な地形タイルを追加取得します。完了すると地図を計算範囲に合わせ、半透明のレイヤーを表示します。
5. 地図の格子をクリックすると、中心の座標、RSSI、マージン、見通し、回折損失、地形断面（60%フレネルゾーン含む）を表示します。通常の地図ドラッグ・ズームも可能です。格子中心が評価点であり、セル内の全地点を評価したわけではありません。
6. 「安定目安」と表示濃度は再計算なしで変更できます。緑は設定したマージン以上、薄緑はその半分以上、黄は0dB以上、赤は閾値未満、灰は標高不足または基地局そのものです。比率は計算可能な格子点数に対する割合であり、実測到達率ではありません。
7. 色を参考に「＋ 端末」で候補地点を追加します。基準端末と伝搬条件が不変なら到達マップは残ります。基地局の位置・アンテナ高、地形原点、伝搬設定、計算範囲、格子間隔または受信アンテナ高を変えると古い結果を消去します。
8. 配置が決まったら従来通り「地形を取得して実験」でAFP実験を実行し、Network Observatoryで確認できます。

## 保存・再現

計算ごとに `experiments/planner/coverage/<run-id>/coverage.json` にField Config、計算条件、格子ごとのRSSI・マージン・判定、使用DEMタイルのURLとSHA-256を保存します。上書きしません。「結果 JSON 保存」では表示設定も含むJSONをダウンロードできます。「Field JSONを保存」は配置とCoverageの設定を保存します（計算結果そのものは別ファイル）。次回の起動でField JSONを開き、同じ条件を再計算できます。保存済み結果だけを地図に再表示するUIは未実装です。

格子点の断面は保存済み結果の条件とDEMキャッシュからオンデマンドで再生成し、予測値・使用タイルのSHA-256が一致することを確認します。プロファイル再生成時はネットアクセスしません。DEMキャッシュを削除・更新した場合はマップを再計算してください。

## 計算量と制約

半径5km / 200mでは1,961格子点（基地局位置1点を除いて1,960リンク）、断面間隔10mなら656,132断面サンプルです。人工DEMで約1.6秒（開発環境の1回の参考測定）でした。実データの取得時間・デコード・PC性能は含みません。半径を広げると、初回のDEM取得やメモリ使用量も増えます。

- 最大半径10km、格子間隔50〜500m、最大10,000格子点・400万断面サンプル。上限を超える要求はDEM取得前に拒否します。全組み合わせが実行できるわけではありません。
- 基地局を中心とした計算範囲全体は原点から各軸±15km以内。必要に応じてField Configで原点を移動します。
- 受信閾値、固定追加損失、単一ナイフエッジ近似は未校正です。森林・建物・時間変動・実機の受信確率等は含みません。緑も安定通信の保証ではありません。
- 標高データがない格子は不明とします（基地局の標高が取得できない場合は停止）。ネットワーク障害や破損タイルはエラーとして停止します。欠損値を0mに置き換えません。
- 予測は単一基地局の直接リンクで、中継によるカバレッジや複数基地局の合成は未実装。
- `--offline` はDEM取得をキャッシュ限定とする機能です。背景地図はネット接続またはブラウザキャッシュが必要です。

## 実装と検証

`coverage.py` を追加し、`terrain.py` の既存設定・地形断面取得を小さな共通関数へ抽出。`planner.py` / `planner.html` に専用APIとレイヤーを追加しました。従来の通信実験8シナリオの全summaryはv0.6と一致。74件のテスト（既存63 + 追加11）成功。GSI形式の人工PNGキャッシュ、点対点モデルとの一致、欠損、上限、結果保存、断面再生成、API認証を確認。Chromiumはこの環境のローカルHTTP制限のため、テスト用タイルとPython HTTP APIへのテストブリッジを使用して操作を検証しました。実際の国土地理院サーバーへの接続とWindowsでのv0.7操作は未確認です。

詳しい設計は `DESIGN-v0.7.md`、従来のField Config・通信実験の操作は `README-v0.6.md` を参照してください。なおField JSONやCoverage結果には自宅などの正確な位置が含まれることがあるので、外部共有には注意してください。
