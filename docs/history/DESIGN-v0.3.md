# v0.3 設計監査と判断記録

目的: 2つの研究（AFP Protocol Research / Radio Field Research）を進める前に、シミュレーション特有の全知性とホストAPIの混同を除く。

| v0.2で見つかった前提 | v0.3の対応 | 残課題 |
|---|---|---|
| AFPNodeとFieldが同じClockを利用 | NodeClock契約、端末別VirtualNodeClock、単調時計ランタイム | 実機時刻同期、再起動時の時計ID |
| AFPNodeとRadioがField.logに集約 | 端末単位のRecorder、Field Recorderを別ストリームに | ESP32の収録とログ回収 |
| ホストの受信ログに物理送信元・グローバルTX IDを渡す | RxFrameはpayload/RSSIのみ、LocalにField情報を拒否 | 実際のUARTフレーム境界 |
| 送信キューがRF終了まで占有される（実機AUX非公開） | ホストUARTキューはUART完了で解放。隠れたmodule queueを仮想専用として分離 | E220で内部挙動を測定 |
| Controllerが端末を直接全知的に起動 | 端末ごとの計画とNodeSession。各コマンドはローカル時計基準 | 実機開始/停止プロトコル、配布方法 |
| 仮想イベントがなくなるまで実行 | 明示的な観測窓を導入 | 実機運用での終了・ログ完全性の確認 |
| Fieldの全イベントから結果を直接集計 | 原記録とmanifestだけを受け取るOffline Collector | 長期・大規模実験時のストリーミング集計 |
| すべての無線失敗理由を可視化できる | Local/Field視点と不明値を分離 | 外部観測機器からの測定ログ契約 |
| 欠損したログと本当の未受信を区別しない | ストリーム件数・完全性・未同期の明示 | 電源断と欠落時の原記録の耐久性、認証 |
| 不正な入力フレームを受けると例外が上がる | AFPNodeでdecode例外を処理しinvalid_frameを記録 | 認証、リプレイ防止、境界条件とDoS対策 |

## 設計境界

AFPNodeはRadioInterfaceとNodeClock、Local Recorderの呼び出しだけで動作する。RadioInterfaceはホストが観測できる情報を返す。Fieldの物理モデルは仮想実験の診断のために存在するが、AFPNodeの判断材料にはしない。将来の時間割制御や経路探索も、端末が現実に取得できる情報で動作することを要求する。

共通にするのは責務・wire format・端末計画・観測契約・集計方法。PythonのコードをそのままESP32に移植できるとは限らない。実機C++実装とPython実装を共通のテストベクトルで検証する。

時刻補正は観測側だけ。AFPの時間同期アルゴリズムとは別問題。仮想時計モデルから既知係数を与えた補正は、実環境で推定する手段の検証とは区別する。

今回は既存の5実験の主要結果維持と、実機から得られる情報だけによるオフライン再集約を合格基準とする。新しいプロトコルの最適化や地形モデルの追加を行わない。
