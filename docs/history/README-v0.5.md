# AFP Lab v0.5 — Map Planner

明野データ実験フィールド / AKENO Field Protocol

v0.4の地形計算と分散Recorderを維持し、端末配置を地理院地図上で編集するローカルWebアプリを追加しました。Python 3.10以上、標準ライブラリのみ。追加パッケージやクラウドサービスは不要です。

## 1. Windowsで起動

ZIPを別フォルダに展開し、コマンドプロンプトから実行してください。

```cmd
cd /d "%USERPROFILE%\Downloads\afp-lab-v0.5\afp-lab"
python -m unittest -v
python planner.py --open
```

ブラウザが開かなければ http://127.0.0.1:8765/ を開きます。コマンドプロンプトは開いたままにしてください。終了はCtrl+Cです。ポートが使用中なら `python planner.py --port 8766 --open` としてください。`planner.html` を直接開く方式ではありません。

v0.4でダウンロードしたDEMを再利用する場合（前回のZIP展開場所が同じ場合）:

```cmd
python planner.py --cache "%USERPROFILE%\Downloads\afp-lab-v0.4\afp-lab\dem-cache" --open
```

この場合、新しいタイルも指定キャッシュに保存します。背景地図と標高タイルは別のデータです。地図表示はブラウザから国土地理院にアクセスし、地形計算はPythonからDEMを取得します。DEMのキャッシュだけを使う場合は `--offline` を追加できますが、背景地図の表示にはネット接続またはブラウザキャッシュが必要です。

## 2. 配置する

1. 初期の3地点はv0.4の仮の候補地点です。地図を拡大・縮小・ドラッグし、標準地図、淡色地図、色別標高図、航空写真を切り替えてください。
2. 「＋ 自宅を配置」を押し、地図上で自宅のアンテナを置きたい地点をクリックします。実際の住所・位置は初期設定していません。新しい端末を観測拠点（最終宛先）に指定します。アンテナ地上高3m、中継可は仮設定です。
3. 端末を選択し、名前、緯度、経度、アンテナ地上高、チャネル、中継可否を編集して「入力を反映」。地図で位置を変更する場合は「地図で位置変更」からクリック。Escで配置モードを解除できます。
4. 不要な仮候補は「削除」。ほかの候補地点は「＋ 端末」で追加。実験には2〜20台、端末間1m以上が必要です。原点は明野周辺（35.785, 138.445）、局所XYの各軸±15km以内が現在のモデルの範囲です。
5. 「配置JSONを保存」で未準備の地理コンフィグをダウンロードできます。次回は「JSONを読み込む」から再利用してください。ブラウザを閉じる前に保存してください。未保存の配置は自動保存しません。

## 3. 実験を実行

観測拠点を選択し、他端末から測定値を1件ずつ送る自動計画を生成します。送信間隔3秒が初期値、0秒は同時送信です。測定値は試験用の文字列です。自宅に観測拠点を追加しても、実際の無線は送信されません。

「同じ地形で同時／時間差送信も比較」は、同一の地形スナップショットを使用した別スケジュールを作成します。自動計画の場合は、時間差送信と同時送信を比較します。同時送信の比較相手には既定3秒間隔を使います。端末2台で送信要求1件しかない場合は1実験のみです。任意の既存コンフィグを読み込んだときは「読み込んだ送信計画を維持」を選べます。元の計画が削除済み端末を参照する場合は実行前にエラーになります。

「地形を取得して実験」を押すと、v0.4のDEMモデルが実行され、その後AFP仮想通信実験と分散ログの集約が行われます。初回は地形タイルの取得にネット接続が必要です。欠損・ネットワークエラーの場合は停止し、人工地形で代用しません。地図背景が表示できない場合は、ネット接続の確認、別の地図レイヤー、または「地図なし」で座標入力が可能です。

地図上の線は、未計算は灰色、計算後は受信マージン10dB以上が緑、0〜10dB未満が黄、閾値未満が赤です。破線は見通しなし（未計算時も破線）。これらの色は研究用の分類であり、安定した通信を保証しません。地形断面、フレネルゾーン、通信イベント、ローカル/フィールドRecorderの視点切替は「Network Observatory を開く」から利用できます。

## 4. 保存されるファイル

```text
experiments/planner/<UTC時刻とランダムID>/
  geography.json       # その実験に使用した配置と計画（未準備）
  prepared-01.json     # DEM由来の地形・リンク情報を固定
  prepared-02.json     # 比較を選択した場合のみ
  traces/01/...        # 各端末、Field Recorder、manifest
  traces/02/...
  experiments.json
  index.html           # ネット接続不要の従来の観測画面
```

各実行は別ディレクトリに保存します。過去の実験を上書きしません。`geography.json` はPlannerに読み込めます。`prepared-*.json` は従来の `lab.py` に直接渡せます。既存の `python lab.py --open` と `python terrain.py geography/akeno.json --compare` も引き続き使えます。詳細は README-v0.4.md。

## 5. プライバシー、モデルと動作確認の範囲

- ローカルPythonサーバーは127.0.0.1だけで待ち受けます。外部公開はしません。ブラウザとローカルAPIの間のみで端末配置と実験設定を送受信します。外部に対しては国土地理院の背景・標高タイルを要求するため、そのタイルに対応する地域は先方に伝わり得ます。住所検索・ジオロケーション・テレメトリーは実装していません。
- 自宅などの座標を含むJSON・HTML・ログの公開には注意してください。ブラウザの「配置JSONを保存」はダウンロード、実験時は上記ローカルディレクトリへ保存します。
- 伝搬計算はv0.4の単一ナイフエッジ近似のままです。樹木・建物・反射・外部干渉などの詳細は未考慮。受信閾値と追加損失は実機未校正。チャネル、周波数、通信速度、受信感度の自動連動も未実装です。これは仮想実験であって実機の送信条件設定ではありません。
- 既存43件、新規10件の合計53件のPythonテストが成功しました。ローカルHTTP APIはPythonによる実通信でテスト済みです。ブラウザの配置・移動・高さ・レイヤー切替・比較結果表示・JSON保存/読込はChromiumのオフラインテスト（テスト用地図画像、人工DEM、APIのフィクスチャ）で検証しました。開発環境はブラウザのローカルHTTP直接アクセスと実地図取得に制約があったため、Windowsの実ブラウザ接続、国土地理院の背景タイルの実表示、実DEMでのPlanner全体の通し試験は未確認です。v0.4の実DEM取得はユーザーのWindowsで成功しています。
- 面的カバレッジマップ、自動配置最適化、実機測定点の地図重ね合わせは未実装。次の研究段階とします。
